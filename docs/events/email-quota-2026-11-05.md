# 验证邮件每日 100 封限制核查

## 已确认事实

- 2026-11-05 只读检查生产运行容器：发信端点为 `https://api.resend.com/emails`，已配置发件人及 API Key。没有读取或输出密钥内容，也没有为核查发送生产邮件。
- `internal/backend/config/config.go` 默认使用 Resend，生产环境禁止覆盖端点；`service/email/email.go` 统一发送，识别服务商的 `daily_quota_exceeded`、`monthly_quota_exceeded`、`rate_limit_exceeded`/HTTP 429。
- 官网代码没有每日 100 封总量开关。`service/auth/service.go` 对同邮箱同验证码用途设置 60 秒冷却、验证码 10 分钟有效；这与服务商账号额度不同。沙龙服务没有邮件发送逻辑。
- [Resend 官方额度说明](https://resend.com/docs/knowledge-base/account-quotas-and-limits)：Free 交易邮件 100 封/日、3,000 封/月，按 UTC 自然日重置（北京时间每日 08:00）。同账号的发信、收信均占额度，每个收件人分别计算。因此该额度不是“仅注册验证”专属；验证码登录、找回密码及其他交易邮件会共用。

## 核查边界

没有登录 Resend 账单/Usage 控制台。生产 Key 调用只读 `/domains` 返回 HTTP 401，没有返回额度响应头，无法确认实际账号套餐、当天用量或历史超额时间；不能把公开免费套餐规则当作已核验的账号账单。当前应用容器日志没有额度错误，日志仅覆盖当前容器生命周期，不代表全部历史。没有通过发送邮件探测配额。

## 最小长期方案

1. 本期沙龙公开查看、会议和讯飞赛事链接完全免官网注册，避免为参会消耗验证邮件；社区发帖继续使用正常账号与邮箱验证。
2. 预计全校宣传可能带来单日超过 100 次邮件需求时，由账号所有者进入 Resend 的 Usage/Billing 确认当前套餐，并升级 **Transactional Pro**。截至核查日，[官方价格](https://resend.com/pricing?volume=50000)为 **20 美元/月、50,000 封/月、无每日额度上限**，超额为 0.90 美元/1,000 封；速率限制仍适用。沿用已有 API Key、域名及发件人，不需要改代码、部署新邮件系统或迁移注册流程。
3. 保留现有 60 秒重发冷却、正常密码登录及会话复用；上线宣传前在服务商控制台查看用量和发送/投递结果。不加入会让 10 分钟验证码过期的跨日排队，也不轮换账号规避配额。

本次只提交核查和方案；未订购套餐、改密钥、变更生产验证规则、添加发送队列或新通知系统。套餐费用需由账号所有者决定，未声称已经解除真实账号限制。
