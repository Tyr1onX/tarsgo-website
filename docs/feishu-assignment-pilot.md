# 飞书作业管理

网站数据库保存作业、原始附件、提交版本、成绩和批改历史，是唯一业务数据源。飞书多维表格只读展示提交历史；机器人负责发布作业和发起批改；培训队员的操作权限始终由网站账号及其组别管理权限决定。

## 身份与权限

1. 每位培训管理员先登录有作业管理权限的网站账号，在「作业管理」点击「绑定飞书」，复制 10 分钟绑定命令，通过「打开飞书机器人」直达机器人私聊并发送。返回网站点击「检查绑定状态」即可确认。旧 `/api/admin/integrations/feishu/bind` 地址重定向至该页面，不再维护独立绑定网页。绑定使用当前飞书应用的 `open_id`，一个网站账号和一个飞书账号保持唯一对应。
2. 绑定后，机器人将该飞书账号加入“培训队员只读”多维表格角色。该角色可查看全部技术组和全部视图，但不能编辑表格、记录、字段或视图，也不能复制或下载整张表。
3. 发布卡片中的组别只从当前网站账号可管理的组别生成。批改、评分入口和“批改下一份”都会重新查询当前飞书操作者映射的网站账号，并再次执行网站组别权限检查。
4. 飞书卡片回调必须具有有效的飞书请求签名、匹配的 Encrypt Key、Verification Token 和应用 ID。请求头时间戳按原值参与 SHA-256 验签，不假设其为 Unix 整数秒或增加五分钟窗口，与[飞书回调验签协议](https://open.feishu.cn/document/event-subscription-guide/callback-subscription/receive-and-handle-callbacks)一致。评分只调用现有 `assignment.Service.ReviewFirst`；重复评分由网站事务拒绝。

## 作业流程

### 发布与教学资料

培训管理员在绑定的机器人私聊中发送“发布作业”，通过飞书原生卡片填写作业名称、要求、组别、截止时间、接收成员和附件要求。发布复用网站现有作业服务和幂等请求标识。卡片不提供本地文件上传控件；发布后可发送“资料 #作业编号”，再发送教学资料文件，最后发送“结束资料”。原始资料保存在网站，上传仅允许用于该组且首次学生提交前。

### 提交、返修和共享看板

新人只在网站提交、返修和查看成绩。每次提交在网站生成新 `submission_id`；后端在原事务成功后，把本次提交及历史版本幂等同步到同一张“作业提交”表。不会为每份提交向培训管理员私聊自动发送附件或评分卡片。飞书同步失败只记录日志，不回滚网站提交；管理员可使用网站已有的重新对账入口恢复缺失记录。

多维表格包含“待批改”“已批改”“返修记录”“全部记录”四个视图，按技术组字段筛选。`当前提交`由网站的最新提交版本推导，仅供待办视图过滤，不是独立业务状态。返修会保留旧版本及批改记录，并为新版本新增一行；旧版本不会继续占用待批改视图。

### 按需批改与连续批改

点击表格里的“去批改”按钮，飞书工作流把提交 ID 和当前操作者传给网站。后端从网站数据库确认提交仍为当前版本、尚未批改，并且操作者有该组权限，然后将现有评分卡片私聊发送给这位操作者。多维表格中的分数、状态和评语不能直接写入网站。

评分成功后，网站先通过 `ReviewFirst` 保存结果和批改历史，再异步同步多维表格；评分结果卡片显示“批改下一份”。点击后网站再次查询该组最早的当前待批改提交，跳过已批改或已被新版本替代的提交。多人同时打开同一份作业时，网站只接受首次有效评分，其他人会收到已处理提示。没有待办时机器人私聊告知并结束。

## 回调安全与配置

飞书业务回调使用 `https://jijiamaster.com/api/integrations/feishu/card-action`。生产回调必须配置飞书后台同一个 Encrypt Key 和 Verification Token；未配置时服务会拒绝业务回调，不再接受旧的仅 token 或固定试点账号认证方式。消息事件只处理机器人私聊；群聊消息不会触发发布或教学资料处理。

所需环境项：

- `FEISHU_APP_ID`、`FEISHU_APP_SECRET`：机器人凭据
- `FEISHU_ENCRYPT_KEY`、`FEISHU_VERIFICATION_TOKEN`：必需的回调签名、解密及令牌校验配置
- `FEISHU_BITABLE_APP_TOKEN`、`FEISHU_BITABLE_TABLE_ID`：作业看板坐标

机器人应用需要按已授权的最小范围开通消息接收/发送、附件上传和多维表格读写能力。多维表格本身需将机器人作为文档应用加入并授予必要管理权限；API 权限不自动授予文档访问权。培训管理员的飞书账号通过只读自定义角色加入看板，不加入公共群聊。

看板按钮工作流使用后端专用 HMAC token，管理员通过受保护的 `/api/admin/integrations/feishu/bitable/workflow-secret` 获取配置值；该 token 不等于应用密钥，不能放入客户端代码或公开群聊。工作流仅传提交 ID 和按钮操作者，不接受任何评分字段。

## 旧文件消息能力说明

网站到飞书私聊的第一阶段附件消息能力已经过独立验收；当前共享看板流程不再自动发送这些附件消息。Bitable 附件副本用于管理员从共享表格查看，网站仍保留原始附件和权限校验。

如之后恢复直接文件消息，应继续区分文件上传 API 成功、消息发送成功和客户端实际打开/预览三种结果，并按格式和飞书客户端真实验收。

## 范围

本阶段不包含每日 20:00 群汇总，不引入认领、负责人、评分会话状态、消息队列或第二套发布/评分服务。
