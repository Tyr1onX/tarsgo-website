# 历史列表与详情重复读取

- 请假汇总历史每 100 次汇总批量读取名单和未过期签回元数据；由原来的 1+2N 次 SQL 变为 1+2×ceil(N/100)，列表顺序及下载状态保持一致，始终排除 BLOB。
- 请假名单按时间区间排序后，仅比较最后一组，去掉分组时对所有既有组的线性扫描；签回材料按已有连续分组号直接关联。
- 社区详情正文与回复共享一次附件查询；回复附件按回复 ID 分组，避免每条回复遍历全部附件。

验证：后端全量测试、vet 通过；MariaDB 15 个现有合成集成测试/子测试通过、零跳过。新增 0/1/101 次请假汇总的查询批次与顺序测试、分组和签回文件对应测试。社区既有真实数据库流程覆盖正文/回复附件和访问权限。未修改 API 响应或前端交互，未做生产性能验证或导航计时。

边界：本批消除重复查询及重复遍历，不等于已完成分页；请假历史结果总量和社区评论总量仍可增长。分页需要与前端展开、历史锚点和下载选择交互同步实施，不能直接截断结果。未部署，无新增导航请求或资源依赖。
