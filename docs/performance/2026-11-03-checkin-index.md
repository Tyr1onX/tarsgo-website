# 签到重复索引收敛

生产只读索引清单确认 idx_community_checkin_user_day 与唯一索引 uk_community_checkin_day 都是完整、升序 BTREE (user_id,day)。恢复生产逻辑备份到隔离库后，对最新签到范围查询和当日点查比较 EXPLAIN，忽略普通索引前后均选择唯一索引，分别为 range/const，无新增 filesort。

迁移 47 使用固定 DDL 删除普通索引，先核对两个索引的唯一性、列顺序、前缀长度和类型；唯一索引缺失或定义不同则停止。重复执行安全，保留每天唯一签到约束。为保持历史迁移行为，本次不修改旧 model tags；未来若新增对 CommunityCheckIn 的 AutoMigrate，需要去掉历史普通索引 tag 或再次执行收敛，不能默认它不会被重建。

恢复库迁移 46→47 前后签到表 CHECKSUM 均为 1027381648。合成 MariaDB 测试覆盖重复执行、正文保留、重复签到拒绝、异常索引拒绝删除；数据库套件 19 项、零跳过。后端全量测试和 vet 通过。

本地隔离 MariaDB 交替执行六轮每轮 100000 行批量插入（含客户端启动开销，无并发线上负载）：有普通索引中位数 153.795ms、无普通索引 116.585ms。此实验仅说明重复维护的成本，不代表生产延迟或吞吐改善；生产只有几十条签到，主要收益是减少冗余和未来写入维护。

部署使用异机备份开关；DDL 存在元数据锁等待和隐式提交，不依赖外层事务回滚。应用回滚不需重建普通索引；确需恢复可用后续显式迁移 ADD INDEX idx_community_checkin_user_day(user_id,day)，不要篡改已应用版本。无前端导航/资源变化。
