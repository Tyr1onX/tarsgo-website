# 数据模型收敛的检查与迁移条件

`scripts/audit-data-preflight.sql` 只读检查当前 schema、表容量估算、周报重复、招新历史字段占用、暂停模块引用及实际索引/外键。输出仅统计与结构，不输出用户 ID、正文或附件。每条语句最多 15 秒；报错或超时表示检查未完成，不能解释为零异常。

用 MariaDB 11.4 客户端和 SELECT-only 账号先在恢复备份或只读副本执行。凭证放在权限为 0600 的客户端配置文件，不写入命令行或提交日志：

```sh
mariadb --defaults-extra-file=/secure/audit-client.cnf --database=tarsgo --batch < scripts/audit-data-preflight.sql > /secure/audit-data-preflight.tsv
```

不要添加 `--force`。只读不代表零负载；重复检查会扫描周报和招新记录。容量中的 table_rows 是 InnoDB 估计值；索引清单是实际 DDL 元数据。输出并不包含生产慢查询、索引使用频率或任命真实性。

## 周报唯一键

目标为 `(user_id, week_start)`。先检查重复用户周；若非零，逐项核对正文、附件和原组别归属，保留档案后再决定合并规则，不能自动删“较旧”记录。新增唯一键需先在恢复备份演练并测锁等待；迁移窗口必须控制并发写入，防止检查后又产生重复。保留应用 users 行锁。确认新约束生效后再独立评估旧组别唯一索引和普通索引是否仍有查询价值。回滚应删除新约束并恢复旧约束，数据合并不能依赖 DDL 回滚。

## 招新新旧字段

当前 `recruitment_status` / `preferred_group_id` 是业务状态来源。`model/registration.go` 已明确旧字段只保留历史；`service/registration/service.go` 的当前筛选、状态流转及聚合使用新字段。因此这里应收敛历史读取边界，不再实现第二套状态同步。

旧字段有值不表示新字段错误。先建立历史页面/导出/外部调用的读写矩阵并验证已关闭届次仍可读取，再把旧字段归档为版本固定结构；在历史读取迁移完成和保留政策明确前，不删除列、旧面试表或历史迁移。后续迁移使用固定 DDL/版本结构，保持空库与历史库升级的结果一致。

## 稳定组别代码与组织任命

组名→业务代码应由真实组别清单核对，一对一映射后先新增 nullable code、回填、验证唯一性，再让后端权限和前端导航读取同一稳定字段。未知组别拒绝推断，不用字符串改名隐式赋权。随后再增加非空/唯一约束；保留组名作为展示值。

组织岗位定义使用现有稳定 position ID；用户任命单独记录有效期和修改人。静态 userId 在不同数据库不保证代表同一个人，不能把本地测试中的缺失用户当作生产任命错误，也不能直接把固定 ID 自动导入所有环境。岗位展示不自动授予系统权限。

## 索引和暂停模块

确认 `community_check_ins(user_id, day)` 的唯一与普通索引是否同时存在，再在隔离样本比较执行计划、读写耗时和索引大小。前缀相同不总意味着可以删；检查外键、排序和覆盖查询。社区 LIKE 中文子串搜索保留，未经召回验证不替换 FULLTEXT。

`skill_node_assignments`、`skill_review_events`、`capability_dimension_sources` 仍参与现行作业删除保护。即便本地统计为零，也不能证明生产无引用。日常通信 API 和旧 URL 的外部调用还需访问日志；不因前端入口暂停而删除历史表。

## 验证边界

本工具不执行迁移、不自动修复或删数据。验证使用隔离 MariaDB 合成数据，不代表生产重复率、容量或索引收益。历史数据核验完成后，每类 schema 修改单独 PR，附恢复演练、迁移前后计数、查询计划和回滚条件。

已在本地 MariaDB 11.4.13 完整执行只读 SQL；另用会话临时周报表验证 NULL 组别、跨组重复及正常单条数据，准确得到 2 个重复用户周、3 条超额记录、1 个跨组用户周和 2 个含空组别的重复用户周。临时表随连接关闭丢弃。

## 可复跑的索引实验

`scripts/audit-reaction-index-experiment.sql` 在会话临时表生成 20 万条互动数据（5,000 帖子、4,000 用户），比较新增两个候选索引前后的真实 `ANALYZE FORMAT=JSON`。只在隔离库执行，需要临时表权限；不会修改业务表。

| 合成查询 | 原扫描行 | 候选索引后扫描行 | 使用索引 |
|---|---:|---:|---|
| 用户 10 的收藏 | 200,000 | 50 | user_id, kind, question_id |
| 帖子 100 的近期点赞 | 40 | 14 | question_id, kind, created_at |

这是单次本地执行的 r_rows。第二项 pages_accessed 从 6 增为 9，不能仅凭扫描行减少就断言整体收益。未测写入成本、真实分布、完整社区权限/搜索/排序 SQL、并发和冷热缓存；第一项独立用户收藏查询也不等价于现有以帖子为外层的相关 EXISTS。因此本 PR 不新增生产索引，不将这两个实验数字当作接口加速倍数。

本地实际索引清单确认签到 `(user_id, day)` 同时有唯一和普通索引；下一步需要恢复生产备份上的查询回归与迁移演练。原始本地实验输出随实施报告留存，执行脚本可复现查询形态。
