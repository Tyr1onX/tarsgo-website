# 统一注册资料与 AI 沙龙报名验证（2026-11-04）

## 实现与兼容性

- 基于 main `753eb88081d023e2e21112ca3a2024e997fd13d0`。先只读检查生产 users、ai_salon_registrations 结构及 schema_migrations=51。
- 迁移 52 只在两张既有表新增可空 is_student；幂等、不回填、不删除旧手机号/性别/校区。新注册只保存姓名、邮箱、密码及学生身份，学生另需学号、学院和年级。旧客户端提交的手机号不写入新账号。
- 账号资料由 `/api/me/profile` 读取、现有 `/api/me` 修改。姓名与头像仍在既有个人主页顶部编辑；学籍字段位于同一主页设置内，邮箱作为已有验证登录标识展示。没有新增学生档案表。历史请假资料仅作账号缺失字段的只读预填，不在读取或报名时回写。
- 学号自动识别仅限已确认的 8 位学院/年份/班级/序号编码，学院前缀 20（用户确认的示例）及 35（[吉大官方本科生公示](https://sg.jlu.edu.cn/info/1396/22323.htm) 中 2023 级学号实例）。第 3–4 位组成 20YY；年份不能超过当前年，班级/序号不能为00。没有找到完整权威学院编号表，其他前缀、位数、研究生及未知编码都允许手动选择入学年份。此功能不代表验证学生身份，不采用研究生招生的三位学院代码来推断本科编码。
- 报名接口不解析身份请求体；同一事务锁定活动及账号，检查资料并创建独立快照。非学生的学号占位键为 NULL，可有多个非学生同时报名。原有账号/学号唯一约束、FIFO、取消释放、重报追加及签到窗口不变。沙龙所有资料维护接口和表单已删除。
- 请假仍要求 8 位数字学号、有效本校学院、原有工作台/审批授权及既有身份锁定。未锁定的请假材料读取账号资料，提交时建立材料身份并锁定；已锁定的姓名、学号及队内身份不随账号修改而变化。旧 PUT `/api/leave/profile` 对旧客户端明确返回410，引导统一入口，不再接受平行修改。
- 核查纳新仍由表单字段规则验证联系电话等独立业务数据，未修改报名表单配置及必要校验。战队组别、系统角色及正式成员身份的维护链路未改动。

## 导航与性能

没有新增路由加载器必须等待的请求或资源；资料和报名历史在页面组件中并行异步读取，沙龙已删除学院列表请求和操作后的额外账号重读。统一资料页按需加载，请假兼容视图请求不阻塞路由。

本机真实浏览器、同一超管/网络下官网→工作台、工作台→管理各4次：标题可见约26–35ms，路由提交约0.4–19ms；每次未观察到 `/api/me` 重读。第1次可能使用现有预取，不称为冷加载。独立匿名文档首次打开沙龙标题可见约66ms。逐请求/API数据在 navigation-results.json；无改动前对照、无生产性能测量，样本不足以给出可信P95，不推断所有网络或所有缓存状态均满足预算。
