# 历史功能收敛与数据保留

## 最终范围

用户确认删除技能树、能力评价及旧分组面试数据；旧报名主要组别按“最终录取组 → 意向组 → 第一志愿”保存。报名主记录、正文、附件、现行初筛/面试/通知/出席和最终结果继续保留。

- 删除停用技能、能力及依赖它们的成长/培养页面、客户端、handler、service 与对应旧测试。
- 解除仍暂停的远征界面对技能/成长接口的依赖；保留远征项目本身。
- 迁移 49 清空 8 张技能/能力表。空表结构保留，兼容上一版应用回退；历史建表类型冻结在 database 包。
- 迁移 50 创建报名档案表；迁移 51 在同一事务中保存快照、删除旧分组面试、清空双志愿审核列及 JSON 的 group_1/group_2。DDL 与数据事务分开，失败不留下半份报名清理。
- 档案快照保存报名编号、表单/人员编号、姓名、表单标题、报名时间、主要组别及名称、组别来源、旧最终结果和归档时现行结果。两种结果分别展示，避免误把历史状态等同于当前流程。
- 新增管理菜单“历史档案”，仅超级管理员可看，每页 25 条，用主键游标分页；服务端再次校验权限、固定 SQL 白名单、Cache-Control:no-store。保留原培养备注的只读查看。
- 作业读取及删除移除已清空技能/能力表的关联查询；提交与审核历史继续阻止删除。
- 表单编辑拒绝恢复双志愿字段，CSV 使用现行单意向组；主要组别历史在独立档案查看。

## 发布与恢复

发布必须使用 DEPLOY_REQUIRE_OFFSITE_BACKUP=1，确认生产机及异机校验成功后再迁移。代码回退不会自动恢复已清理的数据；恢复旧明细需从发布前备份选择性恢复，不能覆盖发布后的新业务数据。

本记录写入时尚未 push/合并/部署；最终状态在任务交付记录补充。

## 导航自查

历史档案页面异步读取，不增加共享路由 loader 必须等待的请求；分页最多读取 26 行，切换类别取消过期请求。未新增无关资源到共享入口。删除停用资源不等同于已测得导航加速，未声称 100/200ms 或 P95 达标。
