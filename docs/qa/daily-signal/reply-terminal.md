# 吉甲基地回信 · Issue #69

关联 [Issue #69](https://github.com/Tyr1onX/tarsgo-website/issues/69)。Draft PR #81 保留为静态交互设计记录；本说明同时记录后续正式实现。静态原型只展示虚构账号与数据，不调用 API、不连接数据库。

## 设计与交互

原型以 PR #82 合并后的唯一工作台 `/dashboard/base` 为基准，复用真实工作台导航、个人身份和主题控制。保留每日通信签到区、情绪选项、年度热力图、同心圆雷达和金色信号点。终端内只保留基地名称、必要状态和一句回信，回信是视觉重点；不显示编号、频道、可见性等参数，不设置手动回放入口。

| 状态 | 展示与操作 |
| --- | --- |
| 签到前 | 雷达静候，显示轻柔的欢迎句。情绪可选，也可直接签到。 |
| 发送中 | 仅在首次签到请求时短暂显示接收状态。 |
| 首次签到成功 | 文案出现一次短促金色波纹，热力图当天点亮，并展示固定文案库中的一句回应。 |
| 同日重访或幂等重试 | 通过账号、服务端日期和当前情绪得到相同文案；不再播放签到动画。 |
| 当天情绪修改 | 保存成功后按服务端返回的新情绪重新推导文案；失败时继续显示旧状态，不伪装保存成功。 |
| 情绪清除 | 重新推导为中性文案；签到日期与热力图方块不变，旧情绪回应不留在页面或可复用缓存中。 |
| 查看历史日期 | 从当前账号既有的私有档案日期和情绪推导该日回应；历史情绪被删除后仅显示中性回应。 |
| 请求失败 | 保留可重试的签到操作和错误说明；回信计算与动画失败不能回滚或阻塞签到。 |
| 减少动态 | 保留相同文字、状态和操作，波纹与位移动效停用。 |

静态演示使用当前标签页的 `sessionStorage` 保存一条虚构回执，以展示刷新后的同日重访；它不是正式实现的数据模型。签到成功状态由一个无障碍 live region 简洁播报，终端标题和回信本身不重复抢读。

## 正式功能规则

- 不新增回信表、字段、接口或单独的回信历史；回信不独立持久化。
- 对每个日期，使用已登录账号的稳定内部 ID、签到档案中的北京时间日期、档案中当前保存的情绪（或 `null`）和固定版本文案库确定性选出一句话。账号 ID 只用于浏览器当前渲染时选择，不返回、展示或写入回信数据。
- 同一账号、日期、当前情绪和文案版本在刷新、重复访问及不同设备上会得到相同文案。相同状态下相邻日期会轮换暖心文案，避免第二天仍收到同一句；不同账号由账号 ID 参与选择。回信不写入本地或服务端存储，任何账号切换都会丢弃当前显示状态。
- 服务端日期和情绪是权威值。重复签到响应（`created: false`）不重播动画；账号切换时先清除旧状态，旧请求的迟到响应不得覆盖新账号。
- 修改情绪后按保存成功的服务端结果重算；清除后使用中性分组。历史回应依赖既有本人档案，不另建数据源。本人以外的用户（包括管理员）不得借由回信显示读取情绪。
- 文案库使用人工审核的类别与版本。文案版本升级时须声明生效日期，并保留旧日期所用的映射，避免部署更新后同一天的回应悄然变化。无法识别的状态安全回落到中性文案。
- 轻幽默由稳定哈希按约 10% 权重抽取；“有点疲惫”没有幽默文案。文案只来自仓库审核内容，不接 AI，不包含真实成员事件、催促、缺勤评价或状态诊断。
- 只对首次成功创建的签到做一次短动画；无音效、常驻旋转、连续签到奖励、积分和排行榜。

## 正式实现范围

- `/dashboard/base` 直接使用现有工作台布局、档案和签到接口；回信只是一句终端文案，不添加回信历史、回执编号、收藏或管理入口。
- 首次签到成功后，使用服务端响应中的日期与状态推导回信，并只播放一次短促波纹。幂等重复访问保留同一文案，不重播动画。情绪保存成功后立即重算，清除后改为中性回应；历史回信直接从本人档案当前情绪推导，因此删除情绪后不会留下旧回应。
- 选择器为纯函数，不进行网络请求、不保存数据、不访问其他账号的情绪。失败文案不会冒充回信成功；签到接口和现有档案权限仍是权威来源。
- 桌面回信区为雷达与正文并列布局；在较窄的工作区增加终端文字宽度，移动端改为紧凑横排，避免正文窄到逐字换行。

## 浏览器截图与验收

静态原型在本机真实 Chrome 155.0.8059.82 中通过浏览器界面完成设计验收，截图与检查使用相同原型版本：

- 视口：桌面 1440 × 1100，移动 390 × 844，窄屏 320 × 800。黑金／白金、签到前、发送中、成功、同日重访、失败、有情绪和无情绪均已逐一查看；更新后的 11 张 JPG 位于 [`reply-terminal-screenshots/`](./reply-terminal-screenshots/)。
- 键盘：使用 Enter 触发签到；移动侧栏可打开，Escape 关闭后焦点状态正确。
- 状态：无情绪签到会点亮今天并收到回应；情绪改为「有点疲惫」后回应随之更新，清除后转为中性，今天的签到方块仍为已发送；失败情景提供可读的 `role="alert"` 提示。
- 动效：标准模式下首次签到成功触发一次金色波纹与文案入场；同日重访不再触发；降低动态偏好下均停用。
- 减少动态：`prefers-reduced-motion: reduce` 下波纹动画时长为 `0.00001s`，内容与操作不变。
- 三种视口的页面宽度均与视口一致，没有横向溢出；浏览器运行期错误为 0。

正式功能另以本地前端和内存中的虚构 API 夹具进行真实浏览器验收，不连接任何业务数据库：

- 桌面视口 1440 × 1100，真实签到、同日重载、状态修改与清除、历史状态删除以及两个虚构账号切换均可操作；删除状态后热力图日期保留、旧情绪不再出现在回信中。
- 移动视口 390 × 844、窄屏 320 × 800 检查终端布局与横向溢出；黑金／白金主题、键盘操作和减少动态偏好复核。
- 所有会写入签到或情绪的验收都使用本地内存夹具及虚构账号，不含生产或真实成员资料。
- 生产发布后只做公开页面与健康检查；如无专用隔离生产账号，不向真实账号写入签到数据，并将写入流程明确记录为未验证。

## 已明确的边界与待确认事项

- **隐私、留存**：当前回信不存储，完全依赖现有本人档案；情绪删除后回应随之中性化。沿用每日通信已有私有权限边界，不新增他人可见内容。若将来需要回信收藏、持久化或分析，应另行定义目的、保留期限与删除规则。
- **时区**：使用签到 API 的北京时间日期，回信跨日边界与签到规则一致。
- **使用范围**：访客可浏览现有公开界面，但只有登录用户能签到并看到自己的档案回应；不公开群体回应或他人状态。
- **待产品确认**：固定文案的审核负责人、下线审批与版本发布人。目前按仓库 PR Review 完成人工审核，不建设管理后台。

## 后续开发建议

本次回信功能复用现有签到与档案接口，后续可由产品负责人定期审核固定文案的新增或下线；涉及文案版本变更时，增加纯函数回归测试，确保相邻日期轮换、历史日期稳定、情绪清除后中性化和版本生效日期均被覆盖。当前实现不需要迁移数据库，也不需要独立后端服务。
