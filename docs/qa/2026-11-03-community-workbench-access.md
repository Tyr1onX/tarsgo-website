# 社区开放、工作台隔离与录取授权

## 权限来源与过渡

- 新注册保持现有默认 `community_member`，注册不增加学校限制。
- `trainee_member` / `formal_member`，或现有 admin / super_admin 系统角色，可以使用内部工作台；组别、业务角色、本人数据检查保持原状。reserve_member 不因身份本身获得工作台权限。
- 临时保留 `users.created_at < '2026-11-03 18:10:00'` 的旧账号访问能力。固定边界为北京时间 2026-11-03 18:10:00（UTC 10:10:00），不能替换成动态 NOW。
- 生产只读预检于北京时间 18:09:52：821 账号，最早 2026-04-18 13:53:52，最晚 2026-10-31 09:58:21；created_at 为 DATETIME(0)，无 NULL/零日期；795 community_member、26 formal_member。数据库 NOW/UTC_TIMESTAMP 相差 +08:00，system_time_zone=CST，应用 TZ=Asia/Shanghai、DB_LOC=Asia%2FShanghai。用户确认上线前不会新增注册。
- 在 SQL 的数据库墙上时间域比较，避免驱动解析时区改变边界；集成测试覆盖前一秒、等于边界、后一秒。无身份批量更新、无 schema 迁移、无新持久权限字段。
- 名单核对完成后删除 model/workbench_access.go 的最后一项 OR 及固定时间常量；其他授权来源不变。

## 实现范围

每次现有会话查用户时顺带计算 workbenchAccess，复用 /api/me 与既有账号刷新，不增加独立权限请求或权限缓存。前端导航、内部路由、个人课表均使用服务端结果。所有内部子路由默认受保护；社区、公开主页、账号设置和纳新报名单独开放。后台角色检查保持原状。

后端保护课表与导入、周报及附件、每日通信写操作、请假访问申请和成员事务、作业/提交/附件、组织目录、工作手册、组别自助确认。每日通信公开 GET 保持匿名空档案体验，不读取无工作台资格账号的个人档案。学籍资料仍是个人设置；原有持 token 的公开假条和活动链接维持原有可见性/凭证检查。社区私有历史问答的作者/本组管理员/超管检查未放宽。

原全局多组别确认会要求用户删去其他组别；已删除该页面阻挡和对应组件，使社区及有效多组别成员无需人工确认即可进入。具体业务仍按其已有组别检查。原组别管理 API 保留供现有管理功能使用。

最终面试录取及纠错复用已有事务和报名行锁，再锁定用户：报名状态、梯队身份、录取组别、审计、结果修订与通知记录一并提交。已有正式身份、系统角色、组别与岗位不覆盖；仅追加缺少的录取组别。重复相同结果不重复写入或追溯历史已录取账号。

纠错读取现有审计内该次录取实际新增的关系，只撤回该次改变。已有身份/组别及岗位、后来正式晋升或新增组长身份受保护；管理员角色从不修改，错误录取给管理员新增的梯队/组别也能正常撤回。已录取报名不能单独改意向组，需先纠正结果再修改并重新录取，防止录取组别与组织关系不一致。没有新增人工审批。

AI 沙龙表、业务和报名流程不变，不创建沙龙组。
