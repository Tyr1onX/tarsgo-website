# 基地项目与 AI 沙龙第一版验收

2026-11-03，基于 `dbe50398bbc001933f151d8738304b24c31a7369`。所有写入仅在本机隔离 MariaDB 的测试库执行，使用虚构账号与活动；未连接生产数据库，未部署。

## 实现与数据约束

- 新增 `/programs`、`/programs/ai-salon`、`/programs/ai-salon/:id`；保留微专业原地址与 `/base`。
- `/programs/ai-salon/registrations` 提供本人历史报名与个人资料；`/programs/ai-salon/manage` 仅超级管理员使用。复用账号认证、现有学院列表和 MariaDB，不发邮件、不授予内部功能权限。
- 迁移 48 在 users 增加学院、年级、学号、校区；复用 real_name、gender。缺失学籍信息从既有请假资料预填；报名资料写回账号，既有锁定的请假材料不变。每次报名独立保存当时资料和账号邮箱；取消后重报仍保留此前取消记录。
- 活动及全部名额操作先锁定同一活动行；报名名额读取使用当前读。数据库分别约束活动内有效账号和有效学号唯一，取消时将有效占位键置空。补位按提交时间、递增序号排序；重报追加新记录，时间相同时也排至队尾。
- 扩容和取消触发自动补位，缩容不能低于正式人数。报名提前关闭后，截止前仍可取消；到截止时间报名、候补、取消全部关闭。活动开始时可签到，结束时关闭；只允许正式报名用户自行签到一次。管理员没有修改报名/签到状态的接口。
- 公开接口不返回容量、名单、报名人数和候补排位；个人 API 只从登录态取本人 ID。管理 API 使用现有超级管理员中间件，所有写入校验来源。导出 UTF-8 CSV，处理表格公式前缀。删除活动时事务删除全部报名及签到，数据库同时设置外键级联删除。
- 海报第一版使用可选 HTTPS 图片地址；内容为纯文本，不增加编辑器或文件存储依赖。网页及导出时间统一显示北京时间。

## 实际验证

- `make frontend-test frontend-check build`：337 项前端测试，334 通过、0 失败、3 项因旧照片源素材不在检出中而按现有条件跳过；类型检查与嵌入前后端构建通过。已有社区编辑器仍有大分包提示。
- `go -C internal/backend test ./...`、`go vet ./...`：通过。普通运行中的可选数据库测试会跳过，以下单独强制执行。
- `scripts/test-database-integration.py`：完整迁移连续执行两次，25 个测试/子测试通过，零跳过，含新增沙龙集成测试。
- `go test -race -count=5 ./service/aisalon ./router`（配置隔离测试 DSN）：连续 5 轮通过，无竞态报告。
- 并发：32 用户同时报名容量 3 的活动，严格为正式 3、候补 29；随后两个取消与扩容至 5 并发，严格为正式 5、候补 25。两个账号同时使用同一学号仅一人成功。另验证绕过服务的数据库唯一约束、候补顺序、同微秒重报、截止与签到边界。
- 权限：匿名/普通账号/普通管理员不能管理或导出，跨来源写入拒绝；伪造用户 ID、邮箱、状态和签到字段无效；本人历史查询不能通过参数切换用户；内部组别无变化。
- Chrome 真实浏览器，生产构建，本机 1440×1000 和 390×844：登录、创建发布编辑、公开入口、正式报名、学号重复拒绝、候补、两类取消、重报排队、取消补位、扩容补位、提前关闭/重开、历史记录、资料同步与快照、签到、签到名单筛选、CSV 下载、删除级联均通过；页面异常为 0。详见 `browser-results.json` 和截图，CSV 仅虚构测试数据。

## 导航与加载回归

- 新页面没有路由加载器等待；列表仅请求公开活动，不读取个人资料。身份复用现有缓存；报名资料仅登录后异步读取。活动详情每 30 秒及窗口聚焦时刷新活动和报名状态，不覆盖正在编辑的资料。
- 保留现有官网→账号菜单→社区→工作台、工作台→展开侧边栏→管理路径；本地 Chrome 各采样 4 次，原始路由提交、标题可见时间和 API 记录在 `navigation-results.json`。这些耗时包含真实菜单展开和自动化点击，不等于单次路由加载耗时；首次/已加载分别标注，样本不足以报告有代表性的 P95，也未做改动前后的对照性能结论。
- 新沙龙页首次导航和独立冷加载单独记录；初次记录中路由提交字段为 null 表示未捕获，未用标题耗时代替。重开独立文档会重新读取身份，不能据此声称身份缓存命中。
