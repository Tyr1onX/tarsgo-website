# TarsGo 主页后端化实施计划

## 状态说明

- 未开始：尚未进入实现
- 进行中：正在实现或验证
- 已完成：自动化测试和人工验收均已通过
- 阻塞：存在必须先解决的问题

## 锁定决策

- 主页后端化覆盖队员主页和管理员数据面板。
- `super_admin` 与全局管理员可以维护全部公告、日程和快捷链接；启用管理组中的组长或组内管理员可以维护自己唯一管理组的内容。
- 内容支持全员可见和指定用户组可见。
- 公告使用纯文本；详情在队员主页左侧抽屉中展示。
- 日程只支持单次事件，按 `Asia/Shanghai` 展示。
- 规则手册和技术文档库使用可配置外部链接。
- 内容使用软删除。
- 后台使用 `/dashboard/admin/portal-content` 单页三标签管理公告、日程和快捷链接。
- 管理员最近动态来自结构化业务事件，不直接展示安全审计日志。
- API 使用 HttpOnly Cookie 认证和 `{code, message, data}` 响应格式。

## 业务术语

- 公告：可发布、置顶、定时生效、定时失效的团队信息。
- 日程：具有明确开始和结束时间的单次团队事件。
- 快捷链接：站内路径或受允许协议保护的外部资源入口。
- 全员可见：所有已登录用户可见。
- 指定组可见：仅目标用户组的当前成员可见。
- 超级管理员主页：超级管理员不受用户组成员关系限制，可看到所有已发布且当前有效的公告和日程。
- 业务事件：可安全展示在管理员数据面板中的结构化动态，不包含请求正文或敏感字段。

## 公共接口草案

- `GET /api/portal/home`：读取当前用户可见的公告、日程和快捷链接。
- `/api/admin/announcements`：公告管理接口组。
- `/api/admin/portal-events`：日程管理接口组。
- `/api/admin/portal-links`：快捷链接管理接口组。
- `GET /api/admin/dashboard`：管理员数据面板聚合接口。

草案接口只有在对应阶段实现并通过测试后，才写入 `doc/schema/task/api.md`。

## 已实现数据定义

- 迁移版本 2：`announcements` 保存标题、摘要、纯文本正文、稳定分类键、草稿/发布/归档状态、置顶、生效/失效时间、可见范围、创建更新人和软删除时间；`announcement_target_groups` 保存公告与用户组唯一关系。
- 迁移版本 3：`team_events` 保存单次日程标题、说明、地点、起止时间、草稿/发布/取消状态、可见范围、创建更新人和软删除时间；`team_event_target_groups` 保存日程与用户组唯一关系。
- 迁移版本 4：`portal_links` 保存名称、安全 URL、受控图标键、排序、启停、新窗口标记、可见范围、创建更新人和软删除时间；`portal_link_target_groups` 保存链接与用户组唯一关系。
- 迁移版本 5：`activity_events` 保存动作键、可空操作者/目标用户/用户组、业务实体引用、安全 JSON 元数据和发生时间；用户或用户组删除时外键使用 `SET NULL` 保留历史。
- `schema_migrations` 按版本有序记录，每个未应用版本使用独立事务；开发种子只补不存在的数据，不覆盖人工修改。

## 已实现接口与页面

- 主页聚合：`GET /api/portal/home`，稳定返回 `announcements`、`events`、`links`、`generatedAt`。
- 门户管理：`/api/admin/announcements`、`/api/admin/portal-events`、`/api/admin/portal-links`；`super_admin` 与全局管理员可全局维护，组长或组内管理员仅可维护自己唯一管理组的公告、日程和快捷链接。
- 组长范围：`GET /api/admin/portal-groups` 返回当前 `admin` 账号担任组长的启用用户组，供公告和日程目标组选择使用。
- 管理员聚合：`GET /api/admin/dashboard`，`admin` 与 `super_admin` 可读。
- 门户内容页面：`/dashboard/admin/portal-content?tab=announcements|events|links`；缺失或非法标签使用 `replace` 回到公告标签。
