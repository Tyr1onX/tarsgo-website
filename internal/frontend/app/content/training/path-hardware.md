# 硬件方向：让电路从图纸走到机器人上

我们用一块带指示灯、供电接口和控制芯片的练习板贯穿学习。最初它只是一份需求，随后会变成原理图、PCB、实物板卡，最后经历上电、下载程序和联调。硬件方向的每个知识点，都会出现在这个过程中的某一步。

## 原理图、PCB 与封装

先在组内使用的嘉立创软件里建立一个小电路：连接器接入电源，一只电阻与指示灯组成简单负载。给器件和网络命名，检查引脚有没有连错。

这里要先区分两个层次：[原理图](?doc=term-pcb)说明电气连接关系，PCB 负责真实的空间位置和铜线布局。例如原理图上两个引脚通过一条网络相连，在 PCB 中就必须找到两端焊盘以及可制造的走线。

为每种器件匹配封装时，要和真实器件的数据手册核对焊盘尺寸、引脚顺序和外形。完成布线后运行 ERC 和 DRC，检查电气规则、线宽、间距等问题，再由设计者核对供电、信号方向和安装空间。

## DC-DC 电源设计

控制芯片、传感器和执行器可能需要不同的供电条件，因此下一步学习 [DC-DC 电源](?doc=term-power)。先写出这块练习板的输入电压范围、所需输出电压、预计电流和允许的纹波，再根据这些指标阅读器件的数据手册。

画一张供电方框图：外部电源 → 电压转换模块 → 控制芯片与接口。比较原理图时，尤其关注输入与输出电容、电感、反馈网络和器件的额定参数；PCB 布局也会影响电源的实际表现。

进入调试时，用组内规定的受控电源和仪器，先核对极性与连接，再逐项测量输出电压、负载变化与温升。把测试条件写清楚，才能判断输出是否达到了设计目标。

## STM32 最小系统与上电调试

有了供电，控制板还需要一个能够运行程序的核心。[STM32 最小系统](?doc=term-stm32)一般涉及芯片供电、去耦、复位、启动配置、下载调试接口，以及所用型号要求的时钟方案。

用数据手册检查每一个关键引脚，绘制原理图和 PCB，准备器件清单和制造文件。拿到实物后，按照[板卡首次上电与调试](?doc=term-bringup)的顺序，从焊接检查、供电检查开始，再连接下载工具，最后运行一个简单的 GPIO 或串口测试程序。

这个过程说明了设计、制造和程序之间的真实关系：原理图正确是第一关，焊接和供电也需要逐关验证。出现异常时，记录它第一次出现在哪一个环节，再追查那个环节的具体条件。

## 主控板的系统集成

校内赛主控板需要将电源、通信和控制电路整合成可制造的系统。它不再是一个孤立电路：主控、通信、电源和连接器必须同时满足机械、电控和硬件的接口要求。

先和其他方向整理接口表：谁发送什么数据、需要怎样的电压、插头和引脚是什么、什么时候进行通信。有关 UART、SPI、I²C、CAN，可以查[常见通信方式](?doc=term-bus)；单片机的外设能力可查[GPIO 与定时器等](?doc=term-peripherals)。

之后按需求 → 系统框图 → 原理图 → PCB → 规则检查 → 制造 → 调试的顺序推进。每个接口都应该有编号、字段或电气规格，以及实际验证方法。

## 电路分析与独立设计

开源硬件项目可以成为很好的教学材料。先研究它的功能目标，再从供电、芯片、接口、布局与布线逐层理解设计选择。与自己的方案对比，问：为什么在这里放去耦电容？为什么选这种连接器？测试时怎样知道它工作正常？

选择一个组内认可的小项目，独立完成需求整理、器件选型、画图、打样与调试。把每次故障、修改与复测记录到同一个项目中，按照[工程验证方法](?doc=term-engineering)形成可交接的结果。

硬件与软件的接口包括程序下载、外设驱动、通信协议与软硬件联调；设计时需要明确对应的引脚、电气条件和数据格式。
