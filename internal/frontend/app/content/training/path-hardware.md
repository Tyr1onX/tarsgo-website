# 硬件方向：一块电路板怎样从想法变成实物

想让一个指示灯在按下按钮时亮起，看上去只有一个很简单的动作。真正做成电路板时，却要考虑电从哪里来、按钮和指示灯怎么连接、器件应该放在什么位置、板子生产回来后怎样判断连接正确。

硬件设计就是把这些问题逐一落到电路、器件和实际测量上。可以从一块小板卡开始，再逐步理解电源、STM32 最小系统和机器人主控板。

## 第一步：电路为什么需要完整通路

指示灯属于发光二极管（LED）。它需要合适的电源与工作电流，通常还需要限流电阻或其他限流电路。电流要形成完整回路，电路才可能正常工作。

一个简化的指示灯电路可以写成：

```text
电源正端 ── 电阻 ── LED ── 电源负端
```

电阻用于限制电流，LED 负责发光。LED 有方向，实际连接还要核对器件的数据手册和极性。按钮可以作为控制通断的器件放入电路，但不同按钮和控制方式对应的接法不同。

这里先出现了两个基本概念：**电压**描述电势差，**电流**描述电荷流动的速率。设计时需要让器件处于其规定的工作条件中。

## 第二步：原理图与 PCB 有什么区别

在电脑上用符号画出电阻、LED、连接器和它们之间的电气连接，得到的是**原理图**。原理图主要表达“哪一个引脚应该连接到哪一个引脚”。

但制造商要生产的是一块实物板。实际器件会占据空间，它们的引脚要焊在具体位置，器件之间还要通过铜线连接。这就是 **PCB（印制电路板）** 要解决的问题。

可以这样区分：

| 表达方式 | 主要回答的问题 |
| --- | --- |
| 原理图 | 哪些引脚在电气上相连？ |
| PCB 布局 | 器件在板上放在哪里？ |
| PCB 走线 | 电气连接怎样由铜线实现？ |
| 封装（Footprint） | 真实器件的引脚与焊盘如何对应？ |

例如，一颗电阻的原理图符号看上去可能都一样，但实际元件有不同尺寸。选错封装，原理图可能正确，器件却无法正确焊到板上。

[原理图、封装和 PCB](?doc=term-pcb)说明网络、焊盘、ERC 与 DRC 的关系。ERC 用于发现部分电气规则问题；DRC 检查设计中的间距、线宽等规则。它们是辅助检查工具，仍需核对真实器件规格。

## 第三步：为什么电源要单独设计

假设电池的电压高于控制芯片可以使用的电压。**把电池直接接到芯片上可能损坏器件。** 因此，控制板常需要电源转换电路。

[DC-DC 转换器](?doc=term-power)的作用是在直流输入与直流输出之间转换电压。设计时先确认几个数：

- **输入电压范围**：电池或外部电源在工作期间可能提供的电压。
- **目标输出电压**：后级器件需要的电压。
- **负载电流**：后级器件实际消耗的电流。
- **纹波与温升**：输出电压的波动和器件发热情况。

例如，一颗芯片需要稳定的 3.3 V，而系统电源可能高于这一电压，就需要符合规格的电源方案。选定转换器后，还需按照其数据手册考虑电感、电容、反馈网络和 PCB 布局。

电源设计不能只根据“万用表测到 3.3 V”判断成功。空载与带负载时的输出、启动过程、纹波、温升，都可能表现不同。真实板卡上电应按组内低压电子调试规范进行，先核对极性、连接与限流条件。

## 第四步：STM32 为什么需要最小系统

一块主控板通常有负责执行程序的芯片，例如 STM32。芯片内部已有处理器内核、内存和外设，但它仍需要外部电路满足工作条件。

**最小系统**指芯片能够完成基本启动与调试所需要的一组电路条件，通常涉及：

- 供电与去耦：为芯片提供稳定的工作电压；
- 复位与启动配置：决定芯片如何进入工作状态；
- 时钟：为内部运行提供时间基准，具体方案取决于芯片型号；
- 下载调试接口：让开发工具能够识别芯片并写入程序。

这些部分的具体引脚与器件选择，应以实际型号的数据手册为准。更多说明见[STM32 与最小系统](?doc=term-stm32)。

板子加工焊接完成后，调试通常由外到内：

```text
检查焊接与连接 → 检查供电 → 识别芯片
                            ↓
                   下载简单程序 → 验证 GPIO/串口
```

如果无法下载程序，问题可能在供电、下载线、调试接口或芯片配置。逐段检查比直接修改应用代码更容易找到原因。具体步骤见[板卡上电与调试](?doc=term-bringup)。

## 第五步：从练习板变成主控板

前面的板卡只有少量功能，而机器人的主控板可能还要连接电机驱动器、传感器和其他控制模块。新增一个接口，意味着新的电气条件与机械限制。

假设板上需要接入两种设备：一个通过 UART 发送测量数据，另一个通过 CAN 总线发送电机反馈。设计时不仅要留出连接器，还要明确引脚编号、信号电平、通信参数和接地方式。[常见通信接口](?doc=term-bus)解释它们的区别。

可以把主控板理解为几类电路的组合：

```text
            电源输入
                ↓
         电源转换与分配
                ↓
传感器接口 → STM32 主控 ← 调试下载接口
                ↓
           通信与执行接口
```

这张图先说明系统关系，再落实到原理图与 PCB。机器人结构还会限制板卡的安装孔、尺寸、连接器方向和线束空间。

## 第六步：打样与联调在验证什么

PCB 设计完成后，可输出制造文件进行**打样**，也就是按设计生产少量样板以供验证。真正的验证并非只检查板子外观，而是对照原理图逐项确认功能。

一条完整的硬件记录可以包括：

| 阶段 | 要保留的信息 |
| --- | --- |
| 设计 | 原理图、PCB、BOM（器件清单）、接口定义 |
| 制造 | 板卡版本、器件型号、装配与焊接结果 |
| 上电 | 电源设置、测量位置、电压与电流 |
| 通信 | 连接方式、收发数据和异常表现 |
| 迭代 | 问题位置、修改依据与复测结果 |

硬件与软件在这里汇合：电路决定信号是否能正确传输，程序决定如何使用这些信号。一个接口“能通信”还需要与实际数据格式、时序和使用场景对应，才能成为可靠的系统。
