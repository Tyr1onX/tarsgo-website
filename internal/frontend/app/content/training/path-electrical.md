# 电控方向：从一条转速反馈开始

设想一台机器人的电机需要保持目标转速。开始时你给它一个控制量，电机能转；换了负载之后，速度却变了。要让它按照目标稳定运行，程序必须知道实际速度、不断比较偏差，并在合适时刻调整输出。这条链路会把 C 语言、单片机、通信、PID 和任务调度自然连接起来。

## 结构体、指针与设备状态

从一个简单的状态开始：目标转速是 100 rpm，测得转速为 86 rpm。两者相差 14 rpm。先在电脑上写一个 C 程序，把目标、反馈和使能状态放到同一个结构体里：

```c
typedef struct {
    int target_rpm;
    int measured_rpm;
    unsigned char enabled;
} MotorState;

int error(const MotorState *state) {
    return state->target_rpm - state->measured_rpm;
}
```

把测量值改成 107，函数应返回 -7。这里的 `struct` 让相关数据有了统一名字，指针让函数访问已有对象，状态标志可以用位运算表示设备的不同状态。相关概念见[指针、结构体与位运算](?doc=term-c)。

继续给状态增加时间戳字段，写一个函数负责更新反馈。此时还没有接入真实电机，你已经建立了一条清楚的数据处理流程：**输入测量值 → 更新状态 → 计算误差 → 输出结果**。

## STM32 与外设控制

电脑负责运行模拟程序，真实机器人还需要[STM32 单片机](?doc=term-stm32)来读取和控制电气信号。先认识芯片、最小系统与下载调试接口，再按顺序练习[GPIO、定时器、中断、PWM、ADC 和 DMA](?doc=term-peripherals)。

建议把一个练习拆成四次实验：

1. **GPIO：** 编写最简单的 LED 状态切换程序，确认程序已经运行并能控制引脚。
2. **定时器和中断：** 让 LED 或日志按固定周期变化，记录实际节拍；理解事件触发和主循环轮询的差别。
3. **PWM：** 输出不同占空比的脉冲，用组内允许的仪器观察周期与占空比之间的关系。
4. **ADC 与 DMA：** 读取一组模拟量，再了解大量采样如何减少 CPU 逐项搬运。

周期控制器的误差计算依赖采样时间间隔；周期不稳定会改变系统的实际响应。

## 设备通信与消息格式

电机驱动器、传感器和控制板之间需要交换数据。即使双方都能正常运行，如果通信参数或字段理解不同，系统也无法协作。

先认识[UART、SPI、I²C、CAN](?doc=term-bus)各自的基本用途。然后用一条模拟转速反馈练习：约定消息的标识、字段长度、数值单位和更新时间。发送端将信息编码成字节，接收端按照同一份说明还原出测量转速。

调试时应逐步回答：供电与连接是否正常？通信参数是否一致？收到的原始字节是什么？解析出来的字段是否符合约定？比如“收到两个字节”只说明传输发生过，只有知道它们的类型、顺序和单位，才能说明电机实际转速是多少。

## 闭环反馈与 PID

现在把前面三课连起来：STM32 按固定周期收到转速反馈，程序把它写入 `MotorState`，计算目标与实际的差。下一步要依据这个差决定新的输出量。

这就是[反馈控制与 PID](?doc=term-pid)的起点。P 关注当前误差，I 累积持续误差，D 关注误差变化趋势。学习时先使用仿真数据观察变化，再在组内测试流程下连接真实设备。分别记录目标、实际、输出和时间，绘制响应曲线。

例如，目标突然从 0 变为 100 rpm，实际值逐步靠近目标；如果参数过于激进，可能出现超调或振荡。你要能够用曲线解释现象、指出改变的是哪个参数，并保留原来的数据作为比较基线。

## 实时任务与模块组织

当传感器采样、控制计算、通信和日志同时进行时，你需要明确每个部分何时运行、怎样交换数据。运行时还涉及[FreeRTOS 任务调度、队列、信号量和互斥锁](?doc=term-rtos)，以及驱动层、中间层、应用层的分层组织。

先把之前的程序拆开：驱动模块负责读写外设，控制模块负责误差与输出计算，应用模块负责管理目标值。随后用一个采样任务向队列写入数据，另一个控制任务读出数据并更新输出。用时间戳检查任务的运行周期和消息传递顺序。

## 整车控制与系统可靠性

整车控制包括底盘运动学与闭环、姿态控制、发射结构控制、PID 参数整定和整车联调。继续沿用相同方法：先识别目标和输入输出，建立单模块验证，再进行跨模块联调。

系统可靠性还涉及裁判系统、看门狗、通信容错、异常保护，以及独立负责一个模块或车组。关注一条关键问题：如果数据延迟、断开或者不合理，系统怎样识别并处理？它关系到真实机器人能否可靠工作。

联调过程涉及环境、代码版本、预期行为、观测结果与复测。相关记录方法见[工程验证](?doc=term-engineering)。
