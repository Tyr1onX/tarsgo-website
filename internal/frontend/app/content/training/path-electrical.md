# 电控方向：让电机按照目标转动

一个电机接上电源，可能就能旋转。但机器人需要的是**可控制的运动**：想让它以某个速度转动，它就尽可能保持这个速度；需要停止时能够可靠停止。

从“电机能转”到“电机按目标转”，需要程序、传感器、通信和控制算法协同工作。电控的知识可以从一个具体问题开始：**目标转速是每分钟 100 转，实际只有每分钟 86 转，该怎样调整？**

## 第一步：把“目标”和“实际”表示成数据

先不考虑真实电路，只分析数字。目标转速是 100，测量转速是 86，它们之间的误差为：

```text
误差 = 目标转速 - 测量转速
     = 100 - 86
     = 14
```

若测量转速变成 107，误差就是 -7。正负号告诉程序实际值处于目标值的哪一侧。

C 语言可以把这个过程写成函数：

```c
int speed_error(int target, int measured) {
    return target - measured;
}
```

函数接收两个整数，并返回它们的差。此处的 `int` 表示整数类型，`return` 表示把计算结果交还给调用者。

真实电机还需要记录是否使能、反馈时间等信息，因此可以使用**结构体**，把相关数据放在一起：

```c
typedef struct {
    int target_rpm;
    int measured_rpm;
    unsigned char enabled;
} MotorState;
```

`target_rpm` 和 `measured_rpm` 的单位都是每分钟转数；`enabled` 表示一个状态标志。`MotorState` 是这组数据的类型名。

当不同函数需要访问同一份状态时，会遇到**指针**：它保存一个对象的地址，函数可以通过地址访问该对象。结构体、指针和位运算的关系见[C 语言数据表示](?doc=term-c)。

## 第二步：把程序放到控制板上

电脑能计算误差，却不能直接给机器人电机发出全部硬件控制信号。控制板通常使用 **STM32 单片机**等微控制器来读取输入、执行程序和控制外设。

[STM32 与最小系统](?doc=term-stm32)解释芯片、供电、启动和程序下载之间的关系。芯片之外还需要电路提供稳定电源与必要连接，程序才能正常运行。

接下来要了解几种[常见外设](?doc=term-peripherals)：

| 名称 | 解决的问题 | 例子 |
| --- | --- | --- |
| GPIO | 读取或输出高低电平 | LED 亮灭、按钮状态 |
| 定时器 | 按硬件时钟计数和触发事件 | 每隔固定时间计算一次 |
| PWM | 输出具有一定周期和占空比的脉冲 | 给某些驱动器提供控制信号 |
| ADC | 将模拟电压转换成数字量 | 读取模拟传感器输出 |
| DMA | 在内存和外设之间搬运数据 | 连续读取一批采样数据 |
| 中断 | 在事件发生时触发处理 | 接收到一帧数据后处理 |

如果控制程序打算每隔 10 毫秒更新一次转速，就需要稳定的执行周期。因为控制算法使用的时间间隔与实际运行间隔不符时，系统的响应也可能偏离预期。

## 第三步：获取真实的电机转速

前面的 86 rpm 只是模拟数字。在实际系统中，这个值可能由电机驱动器或传感器测量，再通过通信接口传给控制板。

通信不仅涉及“线有没有接通”，还涉及双方对数据格式的约定。常见方式包括 [UART、SPI、I²C 和 CAN](?doc=term-bus)，它们在接线、时钟和数据传输方式上各不相同。

假设收到两个字节 `00 56`。仅看十六进制字节并不知道它表示什么。双方还需要约定：

- 这两个字节表示有符号还是无符号整数；
- 哪个字节放在前面；
- 数值单位是 rpm 还是其他单位；
- 消息每隔多久更新；
- 数据丢失时如何处理。

若约定它是按大端顺序编码的无符号 16 位整数，`0x0056` 对应十进制 86，才可以把它解释为 86 rpm。

这也是为什么通信调试要分别检查连接、通信参数、原始字节和字段解释：它们属于不同环节。

## 第四步：根据误差调整输出

现在控制板已经知道目标是 100 rpm，反馈是 86 rpm，也能计算误差 14。**如何从误差得到电机的控制输出？** 这就是反馈控制要解决的问题。

在开环控制中，控制器给出一个固定输出，不根据实际速度修正；闭环控制则按周期重复：

```text
设定目标 → 测量实际 → 计算误差
                         ↓
再测量 ← 电机响应 ← 更新输出
```

[PID 控制](?doc=term-pid)使用误差的当前值、累积值与变化趋势计算控制量。它不是一个“调大就更好”的旋钮组合：

- **P（比例）**主要根据当前误差作出反应；
- **I（积分）**关注误差长期累积的情况；
- **D（微分）**关注误差变化的趋势。

例如，只采用较大的比例作用，响应可能变快，但同时可能产生超调和振荡。积分能帮助减小持续偏差，但过度累积也会产生问题。实际效果还取决于电机、负载和采样周期。

需要比较的是目标转速、实际转速与控制输出随时间变化的曲线，而不只是某一次读数是否等于 100。

## 第五步：让多个工作同时运行

真实机器人要一边接收电机反馈，一边计算输出，还要处理遥控器、传感器和日志。如果所有操作相互等待，控制周期就容易变得不稳定。

**任务**是能够独立调度执行的工作单元。例如，可以将采样、控制、通信分成不同任务。FreeRTOS 提供调度、消息队列、信号量和互斥锁等机制，相关概念见[实时任务与数据交换](?doc=term-rtos)。

```text
传感器/驱动器 → 接收任务 → 消息队列 → 控制任务 → 电机输出
                                      ↘ 日志记录
```

这里消息队列帮助两项任务交接数据。要特别注意数据的时间戳与有效性：控制任务收到的“86 rpm”如果已经是很久之前的反馈，就不能当作最新状态直接使用。

## 第六步：从单个电机走向整车控制

底盘有多个电机时，还要把“机器人向前、转向”等运动目标转换成各个电机的目标值。底盘运动学描述这种对应关系；云台与发射机构则有各自的运动和控制要求。

系统还需要考虑可靠性。例如通信突然中断时，旧指令应当如何处理？传感器数据异常时，控制输出是否应受限？看门狗用于监测程序运行情况，超时后可以触发预定的复位等措施。

这时电控已经不是只写一个算法，而是管理一条完整链路：**目标 → 数据 → 控制计算 → 硬件输出 → 实际反馈 → 故障处理**。问题定位和联调记录可参考[工程验证方法](?doc=term-engineering)。
