# 视觉方向：从一张图片到一条可靠的数据

相机传来的首先是图像，而机器人其他模块需要的往往是可以理解的结果。为了完成这次转换，视觉程序必须把图像读取、处理、结果组织、线程协作和对外通信串成一条稳定的数据流。

本路线接续[AI 与视觉联合基础](?doc=path-joint)，阶段顺序对应[视觉组原始培养路线](?group=vision)：分流阶段、冬令营、下学期与夏令营。我们沿着一张测试图片开始，逐步将它变成能被其他模块读取的数据。

## 第一课：先弄清相机给了你什么

打开一张图片，你看到的是颜色和形状；程序看到的是宽、高和像素值。先用 [OpenCV](?doc=term-opencv) 读取图片，确认分辨率与颜色通道，再做最简单的灰度转换和阈值分割。

```python
import cv2
image = cv2.imread('sample.png')
if image is None:
    raise FileNotFoundError('sample.png')
gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
_, binary = cv2.threshold(gray, 120, 255, cv2.THRESH_BINARY)
cv2.imwrite('binary.png', binary)
```

这段程序用阈值将像素分成两类。你可以修改数值 120，观察二值图怎样变化；进一步提取轮廓，计算候选区域的面积和边界框。这个过程让你认识从像素到几何信息的第一条路径。

**先做两次测试：** 用原来的图片运行一次，再用光线不同的图片运行一次。记录参数、处理结果和失败现象。你会发现图像处理的结果与输入条件密切相关。

## 第二课：用 C++ 整理识别结果

当程序开始处理连续图像，下一步要给数据一个统一结构。原文要求进阶 C++，包括 class、template、Lambda 和 STL 容器。可以先从一个最简单的结果结构入手：

```cpp
struct Detection {
    double x;
    double y;
    double confidence;
    bool valid;
};
```

用 `std::vector<Detection>` 保存一帧中的多个结果，写函数筛选有效区域。再增加时间戳和图像尺寸字段，思考别的模块需要哪些信息。通过这个练习，类、容器和引用不再只是语法名称，而是在帮助你组织一条可以交接的数据。细节可读[C++ 概念页](?doc=term-cpp)。

**检查：** 能追踪一条 `Detection` 从图像处理处产生、经过哪些函数、最后由谁读取；每个字段都有明确定义和单位。

## 第三课：理解神经网络为什么会出现

阈值方法简单、容易解释，但面对复杂背景、遮挡和光照变化时可能很脆弱。这时再接触[神经网络、训练与推理](?doc=term-neural)。模型通过样本学习参数，推理阶段将新图像变成预测结果。

选择一个组内认可的示例模型，用一组来源清楚的测试图像运行推理。把预测正确、误检和漏检的案例各自保存，分析它们与输入条件有什么关系。了解数据集、标签、损失函数和置信度，是理解输出而不是只盯着分数的关键。

**检查：** 能说清模型输入、输出和评估样例，比较人工图像处理规则与学习型方法在同一问题上的特点。

## 冬令营：让连续数据顺畅地流动

相机会持续提供图片，算法处理每一帧需要时间，通信模块又要把结果发给其他设备。由此引出[多线程、消息队列与串口](?doc=term-concurrency)。

先用模拟数据实现三个环节：采集线程生成带序号的结果、处理线程消费结果、通信任务输出整理后的消息。使用时间戳和日志检查数据是否延迟、重复或丢失，然后再将输出字段与电控共同确定。UART 等通信方式的特点，可查[通信协议概念页](?doc=term-bus)。

**检查：** 在日志中能沿着序号追踪一条消息的产生、处理和发送过程；知道哪些数据需要同步、哪些模块负责处理超时。

## 下学期：同时考虑稳定性与响应速度

视觉数据会受到噪声影响，结果突然跳变可能给后续处理带来困难。阅读[滤波与延迟](?doc=term-filter)，对一组模拟测量值分别使用移动平均和指数平滑，画出处理前后的曲线。比较平滑效果时，还要观察突变发生后多久才能跟上。

继续学习 Linux、深度网络与控制算法时，可以把每次练习的输入、输出、参数和环境保存在项目目录里。这样以后修改算法，就能使用同一份样例复测，知道改进是否真实发生。

## 夏令营：把模块放进机器人系统

原始路线的目标是理解自瞄系统结构并参与功能的上车联调。进入这一阶段，先从系统层面梳理采集、结果产生、状态处理与电控接口，明确每段的数据格式与有效性要求，再按组内测试流程将模块逐一接通。

真正需要展示的成果是**可复现的功能改进**：保留修改前的数据与日志，记录修改内容，在相同条件下复测；参考[工程验证记录](?doc=term-engineering)写成别人可以继续检查的说明。
