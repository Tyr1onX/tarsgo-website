# 视觉方向：机器人怎样从图片中得到信息

一张照片对人来说包含颜色、物体和位置，但相机交给程序的首先是一组数字。计算机视觉要做的事，就是把这些数字加工成可以理解、可以使用的结果。

例如，程序要在一张图片中找出某个颜色明显的物体。最基础的方法不需要神经网络，先了解**像素、颜色、阈值和区域**即可。

## 第一步：图片在程序里是什么

数字图片由许多小点组成，每个小点叫作**像素**。图片的宽和高描述有多少列、多少行像素。

彩色图像通常由多个颜色通道表示。以常见的 RGB 为例，一个像素可以用红、绿、蓝三个分量描述颜色。OpenCV 在读取常见彩色图片时，默认经常采用 BGR 通道顺序，这与 RGB 的排列不同。

**灰度图**用一个亮度数值表示一个像素。对于常见的 8 位灰度图，数值范围是 0 到 255：0 接近黑色，255 接近白色。

[OpenCV 与图像处理](?doc=term-opencv)说明图片数据、颜色空间与轮廓的关系。

## 第二步：怎样从图片里挑出目标区域

假设一张灰度图中，背景比较暗，目标比较亮。可以设定一个阈值 120：

- 像素值大于 120，标记为白色；
- 其他像素，标记为黑色。

这样生成的黑白图叫作**二值图**。它把原来丰富的灰度信息压缩成“符合条件”和“不符合条件”两类。

用 Python 与 OpenCV 表示：

```python
import cv2

image = cv2.imread("sample.png")
if image is None:
    raise FileNotFoundError("sample.png")

gray = cv2.cvtColor(image, cv2.COLOR_BGR2GRAY)
_, binary = cv2.threshold(gray, 120, 255, cv2.THRESH_BINARY)
cv2.imwrite("binary.png", binary)
```

代码的处理过程是：

```text
读取彩色图片 → 转灰度 → 根据阈值分类像素 → 保存二值图
```

在相同图片中把阈值改为 80 或 160，保留下来的像素会变化。图像亮度变化也可能影响处理结果，因此阈值并不是脱离拍摄环境就永远适用的常数。

## 第三步：从白色像素得到一个位置

二值图标记的是许多像素，但机器人需要的可能只是某个区域的位置。

可以对二值图提取**轮廓**：轮廓描述某个区域的边界。再根据轮廓计算面积、边界框和中心点等几何量。

例如程序找到一个宽 40 像素、高 20 像素的候选区域。边界框能描述它在图片中占据的位置，但它仍只是**图像坐标**，并不自动等于机器人前方多少米的位置。要得到真实空间位置，通常还需要相机标定、几何关系或其他测量信息。

这是视觉系统中重要的一道分界：**识别图片里的位置**与**估计真实空间的位置**是两个不同任务。

## 第四步：怎样保存每一帧的检测结果

相机持续产生新图片，程序也会持续得到新结果。比起单独保存一个坐标，更合理的是给每次检测一个明确的数据结构：

```cpp
struct Detection {
    double x;
    double y;
    double confidence;
    bool valid;
};
```

- `x`、`y` 表示约定坐标系下的位置；
- `confidence` 可能用于表达结果的置信程度，含义取决于算法；
- `valid` 表示这一条结果是否有效。

实际系统还可能需要时间戳、帧编号和坐标系说明。C++ 的结构体用于组织这些相关字段；`std::vector<Detection>` 可以保存同一帧中的多条结果。[C++ 类型与容器](?doc=term-cpp)解释这些表达方式。

## 第五步：阈值方法为什么会遇到局限

阈值分割依赖人为设定的规则。当目标颜色接近背景、光照发生变化、部分目标被遮挡时，同一组规则可能难以稳定识别。

**神经网络**提供另一种思路：根据带有信息的样本，通过训练学习模型参数。训练完成后，模型对新的输入进行**推理**，给出预测结果。

这三个名称必须区分：

| 概念 | 含义 |
| --- | --- |
| 数据集 | 用于训练或测试的图片等数据 |
| 训练 | 根据样本和目标调整模型参数的过程 |
| 推理 | 使用训练好的模型处理新图片 |
| 误检 | 把不符合目标的内容判断成目标 |
| 漏检 | 图中有目标，但算法没有检出 |

神经网络也可能误检和漏检。模型输出需要在不同环境与数据上验证，才能判断它适合哪些使用条件。参阅[神经网络、训练与推理](?doc=term-neural)。

## 第六步：连续图片怎样组成实时系统

处理一张图片和持续处理相机画面是两种不同的工作。相机可能持续产生新帧，而一次识别计算需要一定时间。如果处理速度跟不上采集速度，数据就可能积压。

因此视觉程序常会划分工作：

```text
相机采集 → 图像队列 → 图像处理 → 检测结果 → 通信输出
```

**线程**是一条执行路径，多个线程可以并发工作；**队列**用于在生产数据的模块和消费数据的模块之间交接数据。

例如采集线程给每帧添加递增编号，处理线程完成检测后保留对应编号。通过编号和时间戳，可以判断结果是否被重复使用、丢失或延迟。

相关机制见[多线程与数据交换](?doc=term-concurrency)。

## 第七步：结果为什么要滤波

假设目标在图片中的水平位置连续测得：`100、101、99、120、102`。其中 120 可能来自测量误差，也可能是真实快速运动。

**滤波**尝试从连续数据中提取更稳定的估计。例如取最近几个测量值的平均，可以减小部分随机波动，但也会让结果对突然变化反应更慢。

因此需要同时观察两件事：结果是不是更稳定，以及结果是不是跟得上真实变化。[滤波、噪声与延迟](?doc=term-filter)说明移动平均和指数平滑的区别。

## 第八步：视觉结果怎样交给机器人

在机器人系统中，视觉结果通常还要发给其他控制模块。通信时需要约定坐标系、时间戳、字段顺序、单位和有效性判断。

例如一个检测结果的 `x=120` 只有在明确“120 代表哪个坐标系的什么单位”时，接收方才能正确使用。通信可以通过串口等方式进行，具体规则见[UART 等通信方式](?doc=term-bus)。

**自瞄系统**属于视觉信息与机器人控制紧密协作的场景。图像采集、目标检测、状态估计和电控执行各有职责。排查问题时要先看错误出现在哪个环节，再结合时间信息与记录复现现象。

从像素开始，到最后把结果交给控制模块，视觉程序形成了一条完整的、可以逐段检查的数据流。
