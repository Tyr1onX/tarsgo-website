# 计算机基础

## 计算机怎样执行一个程序

双击打开一个应用时，屏幕上出现窗口，程序开始响应鼠标和键盘。背后发生的是一系列协作：程序文件保存在磁盘中，操作系统把需要的内容加载到内存，处理器执行指令，最后由显示设备呈现结果。

可以把这个过程理解为在桌面上做一道题：**磁盘像书架，内存像正在使用的桌面，CPU 像实际计算的人。** 书架能存放大量资料，但每次计算仍需要把眼前使用的资料放到桌面上。这个比喻只用来区分职责：真正的 CPU、内存和存储设备通过电子电路交换数据。

### 五种常见硬件

| 名称 | 负责的工作 | 一个能观察到的例子 |
| --- | --- | --- |
| CPU（中央处理器） | 执行程序指令、计算和控制 | 编译程序、压缩文件时会使用处理器 |
| 内存（RAM） | 暂时保存运行中的程序和数据 | 同时打开多个大型应用会占用更多内存 |
| SSD / HDD（存储设备） | 长期保存系统、软件和个人文件 | 保存照片、安装软件、存放代码 |
| GPU（图形处理器） | 处理图形和适合并行计算的任务 | 绘制游戏画面、部分 AI 模型计算 |
| 主板 | 通过接口与电路连接各类部件 | 处理器、内存、存储设备在主板上协作 |

例如，一台电脑标注“16 GB 内存、512 GB SSD”。前者描述运行程序时可用的内存容量，后者描述可存储多少文件。**磁盘还有空间，不等于运行中的程序就有足够的内存。** 这也是为什么同一台电脑能保存大量视频，却可能在同时打开许多软件时变慢。

程序运行速度还会受到 CPU、磁盘读写、散热和软件本身的影响。“电脑很卡”只是现象，要观察具体是哪一项资源成为瓶颈。

### 在电脑上查看这些信息

| 系统 | 硬件与系统信息 | 运行时资源占用 |
| --- | --- | --- |
| Windows | 设置 → 系统 → 系统信息 | 任务管理器 → 性能 |
| macOS | 苹果菜单 → 关于本机 | 活动监视器 |
| Ubuntu | 设置 → 关于 | 系统监视器等工具 |

例如，在 Windows 任务管理器中，CPU 利用率表示一定时间内处理器的忙碌程度；内存占用显示程序正在使用的内存资源。二者描述的是不同的工作状态。

## 操作系统为什么存在

硬件提供计算能力，但每个应用都需要读取文件、分配内存、显示窗口和使用网络。**操作系统负责管理这些公共资源，并向程序提供统一的使用方式。**

Windows、macOS、Ubuntu 都是操作系统。浏览器、编辑器、聊天软件和编译器是运行在操作系统上的应用程序。

例如，两个程序同时保存文件时，应用通常通过操作系统提供的文件接口访问存储设备，而不是各自直接控制磁盘的电路。操作系统也负责协调多个程序使用处理器的时间。

这里有三个容易混淆的概念：

- **程序**：保存在磁盘上的指令和文件，例如某个应用的可执行文件。
- **进程**：程序被启动后形成的一个运行实例。一个程序可以启动多个进程。
- **文件**：保存的数据，可以是文档、照片、代码或可执行程序。

关闭应用通常会结束相应进程；写入并保存的文件仍留在存储设备中。

## 文件、文件夹和路径

软件开发会产生很多文件：代码、图片、配置和测试数据。**文件夹（目录）用于把相关文件组织在一起；路径用于准确指明位置。**

例如有这样一组文件：

```text
tarsgo-practice/
├── notes.txt
├── data/
│   └── speeds.txt
└── materials/
    └── notes-backup.txt
```

`notes.txt` 在项目根目录；`speeds.txt` 位于 `data` 子目录；`notes-backup.txt` 则在 `materials` 里。它们是三个独立的文件。

### 绝对路径与相对路径

绝对路径从一个固定起点说明位置。Windows 可能使用 `C:\Users\用户名\Documents\...`，Linux 和 macOS 常使用 `/home/用户名/...`、`/Users/用户名/...`。

相对路径则以**当前所在目录**为起点。如果当前目录是 `tarsgo-practice`，那么：

- `notes.txt` 指向该目录里的文本文件。
- `data/speeds.txt` 指向 `data` 子目录里的数据文件。
- `../` 表示上一级目录。

因此，程序报错“找不到 `data/speeds.txt`”时，除了检查文件是否存在，还要检查程序运行时的当前目录。**文件存在，但相对路径的起点错了，也会读取失败。**

### 文件名、扩展名和内容

文件名末尾的 `.txt`、`.png`、`.py` 通常称为扩展名，用来提示文件的类型：

| 扩展名 | 常见内容 |
| --- | --- |
| `.txt` | 纯文本 |
| `.png` | 图片 |
| `.py` | Python 源代码 |
| `.cpp` | C++ 源代码 |
| `.md` | Markdown 文档 |

扩展名只是文件名的一部分；真正的数据格式由文件内部的编码和结构决定。把一张 `.png` 图片改名为 `.txt`，图片数据仍然是图片数据。

**复制**会产生另一份文件；**移动**会改变文件的位置；**重命名**会改变名字。这三种操作对原有目录结构的影响不同。

## 软件为什么有版本与依赖

同一个程序可能存在不同版本，例如 1.0、1.1、2.0。版本号用于区分软件发布时的功能和实现，具体编号规则由项目决定。

安装软件时，还要区分**操作系统**和**处理器架构**。常见的处理器架构包括 x86-64 和 ARM64。软件包需要与当前运行环境匹配，才能正常安装和执行。

有些程序依赖其他程序或代码库。举个例子：一段 Python 代码使用 OpenCV 处理图片，运行环境就需要安装相应的 Python 库。这样的外部条件叫作**依赖**。

包管理器负责安装、更新或移除软件，有时还会帮助处理依赖关系。Windows、macOS 和 Linux 有不同的安装方法；每种工具的实际要求以其对应版本文档为准。

[Git](?doc=git) 是常见的版本管理工具，它本身也需要安装，作用是记录文件随时间发生的变化。

## 浏览器打开网页时发生了什么

在浏览器输入 `https://example.com` 后，浏览器要先找到网站，再和网站交换数据，最后把页面显示出来。这个过程包含几个不同的环节。

### 第一步：建立网络连接

电脑通常通过 Wi-Fi 或网线连接到路由器，再通过网络服务商与外部网络通信。**连接到 Wi-Fi** 只说明设备已接入某个无线网络，并不能单独证明外部网站一定可访问。

### 第二步：把网站名字转换为地址

人更容易记住 `example.com` 这样的**域名**；网络通信则需要可以寻址的地址。DNS（域名系统）负责把域名解析为相应的网络地址。

可以把 DNS 理解为查地址的过程：知道一个名称，还需要查出该名称对应的可访问位置。如果 DNS 查询失败，浏览器可能报告找不到服务器，即使 Wi-Fi 仍然正常。

### 第三步：通过 HTTPS 通信

浏览器获得地址后，与网站建立连接。`https://` 表示使用受 TLS 保护的 HTTP 通信：TLS 用于加密传输、验证服务器身份等；HTTP 规定网页请求和响应的形式。

例如，浏览器发送“获取首页”请求，服务器返回网页数据。浏览器接着解析 HTML、样式和图片资源，在屏幕上组成页面。

### 第四步：根据现象定位问题

| 看到的现象 | 对应的检查方向 |
| --- | --- |
| 多个网站都打不开 | 本机 Wi-Fi、网线、网关和互联网连接 |
| 某个域名无法解析 | 域名拼写与 DNS 解析 |
| 某个网站连接超时 | 网站服务状态与网络路径 |
| 显示 HTTPS 证书警告 | 网站身份、证书及系统时间 |
| 页面能打开，但图片或样式缺失 | 具体资源地址或请求结果 |

例如，聊天软件能正常联网，但 `example.com` 的域名解析失败，意味着“整个电脑没有网络”并不是唯一可能原因。把故障定位到具体环节，才有办法针对性地处理。
