# ROS 2 的节点、话题和消息
机器人程序往往由多个模块组成。ROS 2 提供一种组织模块及其通信的方式，让传感器、定位、规划与控制能够分别运行并交换数据。
## 一个最简数据流
```text
里程计节点 --发布消息--> /odom 话题 --订阅消息--> 规划或监控节点
```
- **节点（Node）**：运行某项功能的程序组件。
- **话题（Topic）**：适合连续数据流的发布/订阅通道。
- **消息（Message）**：双方共同约定的数据结构，例如位置、速度和时间戳。
- **服务（Service）**：适合请求后获得响应的交互。
参数用于配置节点行为。话题名称与消息类型都必须兼容，发布与订阅才可以正确交换数据。

常用检查命令包括 `ros2 node list`（节点列表）、`ros2 topic list`（话题列表）和 `ros2 topic echo`（消息内容）。

## 为什么要把机器人程序拆开

假设机器人同时读取传感器、估计位置和规划运动。如果所有功能都写在一个大程序里，修改其中一项可能影响其他部分。

ROS 2 提供组织机器人模块和通信的工具，允许把不同功能放在不同节点中。

例如，一个节点负责发布里程计数据，另一个节点订阅并显示这些数据。发送方负责产生数据，接收方只需要约定好的消息格式。

## 节点、话题与消息的对应关系

```text
/odometry 节点
      │ 发布
      ▼
    /odom 话题
      │ 订阅
      ▼
/monitor 节点
```

这里节点名称与话题名称只是示例。**话题**相当于数据交换的通道，**消息**则是通道上传送的数据结构，例如位置、速度和时间戳。

同名话题仍需要兼容的消息类型，双方才能正确理解数据。

## 话题和服务的区别

话题适合持续发布数据，例如每隔一段时间发送新的位置估计；服务适合某个节点发起请求，另一个节点给出响应的交互。

ROS 2 还提供参数等机制用于配置节点行为。具体系统可能使用不同的节点、话题与通信方式。

## 从命令看到运行结构

```bash
ros2 node list
ros2 topic list
ros2 topic echo /odom
```

这些命令分别查询节点、查询话题、显示指定话题的消息内容。只有在对应节点与话题存在时，最后一条才能显示相应数据。
