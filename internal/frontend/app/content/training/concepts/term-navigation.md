# 导航不是一条孤立的路径
机器人导航通常需要知道环境是什么样、自己在哪里、准备去哪里，以及下一步怎样安全地移动。
## 一次导航任务怎样流动
```text
传感器 → 环境表示/地图 → 定位 → 全局路径 → 局部运动规划 → 控制
```
**全局规划**在更大范围内寻找从起点到目标点的路线；**局部规划或控制**需要根据当前状态和附近障碍持续调整。不同框架对模块命名与职责划分可能不同，以实际项目实现为准。
## 导航任务实例
从实验室一端移动到另一端，地图告诉机器人哪些区域可通行，定位提供当前位姿，规划模块生成路线；若前方突然出现障碍，局部模块应当根据新的信息作出响应。

## 从起点到终点要回答几个问题

设想机器人在房间的一边，目标在另一边，中间摆着桌子。直接朝目标移动会撞上障碍，因此需要知道环境哪里可以通行。

地图提供环境表示，定位提供机器人当前位姿，规划负责寻找或调整路线，控制负责让机器人实际运动。

## 全局和局部分别做什么

**全局规划**通常根据较大范围的地图和目标点规划路线。它解决的是整体从哪里经过。

**局部规划或局部控制**则关心附近障碍和当前运动状态。出现临时障碍时，局部模块可能调整速度、改变方向或触发重新规划。

具体软件框架的模块划分可能不同，但“整体路线”和“当前运动”是两种不同层次的问题。

## 怎样区分导航故障

| 现象 | 首先观察的内容 |
| --- | --- |
| 地图上位置明显错了 | 坐标系、定位与时间同步 |
| 规划路线穿过障碍 | 地图数据、规划配置、障碍表示 |
| 路线正确但走偏 | 控制输出、底盘反馈与定位 |
| 临时障碍出现后反应迟缓 | 传感器更新、局部规划与执行周期 |

这张表只能作为定位问题的起点，最终需要结合真实数据与程序运行逻辑确认原因。
